## telefuser
**项目定位**  
这是一个从 TeleFuser 中抽出来的推理服务平台。主要负责把已有模型能力包装成标准服务，让前端和接口调用方都能用同一套方式启动服务、提交任务、查看结果和管理 GPU 资源。

**整体架构**  
项目分为四层：

1. **服务接口层**  
   对外提供 HTTP API，包括任务提交、任务状态查询、结果获取、文件访问，以及兼容 OpenAI 风格的图片/视频生成接口。

2. **任务与执行层**  
   负责接收生成请求，分配任务 ID，管理任务状态，调用后端模型执行，并把输出文件、错误信息和元数据整理成统一结果。

3. **模型接入层**  
   适配现有 TeleImage、TeleEdit 业务代码；

4. **服务控制层和前端层**  
   控制层负责启动、停止、重启模型服务，查看健康状态、日志和 GPU 占用。前端 Studio 已经支持文生图任务提交、结果展示、历史记录、服务状态查看和服务启停。

**已实现功能**  
目前已经接入 TeleImage 文生图和 TeleEdit 涂抹编辑两个服务。服务端具备任务队列、状态查询、结果管理、文件下载、健康检查、服务注册和控制接口。前端已有可用的 Studio 控制台，能完成基础生成流程和服务管理。

**服务化抽取情况**  
已经把通用能力从具体模型里抽出来了，包括统一请求/结果协议、任务生命周期管理、模型适配器、服务启动配置、日志管理、GPU 选择、服务注册表和控制 API。

**多卡加速情况**  
支持三类部署方式：单卡服务、单服务多卡、多副本并发。配置里可以指定使用几张卡、使用哪些卡，以及是否拆成多个副本。

**量化代码情况**  
量化能力已经单独抽成模块，不再散落在业务服务里。当前代码里有量化配置、能力清单、权重转换、量化 Linear、FP8 GEMM 包装和 kernel 加载逻辑。平台清单里已覆盖 FP8、INT8、NVFP4/FP4、MXFP4、MXFP8；
